# Security Policy

## Supported versions

Security fixes are applied to the latest released version and the default branch.

## Reporting a vulnerability

Use GitHub's private vulnerability reporting feature for the repository. Do not open a public issue for a vulnerability that could expose secrets, execute untrusted code, damage data, or bypass authorization.

Include the affected skill or script, impact, reproduction conditions, and any safe proof of concept. Remove credentials, private repository content, and personal data from the report.

The maintainers will acknowledge a complete report, investigate it, and coordinate disclosure and a fix according to severity. This project contains instructions and local validation scripts; it does not operate a hosted service or collect user data.
